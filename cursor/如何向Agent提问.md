# 如何向 Agent 提问（可复用）

基于「概念听不懂 / 边界不清」时回答容易飘的问题，整理成可复制模板。  
目标：强制 Agent **用当前仓库真实文件**解释，而不是空讲概念。

## 复制到其他仓库用法

任选其一即可：

1. **贴进对话**：把本文「4 边界 + 公式」或某个场景模板整段粘到问题前面。
2. **放进目标库**：复制本文件到目标仓库的 `docs/` 或 `.cursor/`，提问时 `@如何向Agent提问.md`。
3. **只带走模板**：复制下方「推荐提问公式」或 A/B/C 任一模板，换掉尖括号里的内容。

这是给人用的提问清单，不是给 Agent 的业务 SOP；不必做成 Skill。

---

## 问题出在哪

「名词是什么」类问题若没锁下面三件事，回答就会停在科普：

1. **解释对象**：行业概念 / Cursor 机制 / 当前仓库怎么落地——三者混在一起
2. **证据来源**：没要求「打开某某文件再讲」，Agent 就用通用比喻
3. **结束条件**：没说「听完我要能做什么决定」，所以没有验收

| 笼统问法 | 边界清晰的问法 |
| --- | --- |
| Skills 是什么 | 本仓库哪个文件是 Skill？何时加载全文？ |
| 概念一大串一起问 | 一次只对比 Rule vs Skill |

---

## 每次提问前的 4 边界（复制即用）

用下面四行当开头，缺一行就先自己补全：

1. **范围**：只讲 Cursor 机制 / 只讲本仓库 / 只讲我要不要新建文件  
2. **证据**：必须引用仓库里的真实路径与片段；没有就说「仓库里没有」  
3. **对比**：一次只对比 2 个概念（如 Rule vs Skill），不要串 Prompt / LLM / MCP  
4. **验收**：回答结束时我应能做出一个具体动作（例如：这段该进 Rule 还是 Skill）

---

## 推荐提问公式

```text
【范围】只根据当前仓库解释，不要行业科普。
【对象】<Rule | Skill | Prompt | …> 在本仓库对应什么文件？
【机制】它什么时候进入上下文？举我这句话：「…」会不会触发？
【对比】和 <另一个> 的差别只用「加载时机 + 内容形态 + 一个例子」说明。
【验收】最后用表格告诉我：这类内容以后写进哪。
【禁止】不要只给类比；没有文件就直说没有。
```

## 三类高频场景模板

### A. 搞清一个 Cursor 概念

```text
只解释 Cursor 里的 <Rules|Skills>，结合本仓库：
1. 列出相关文件路径
2. 用 frontmatter 说明何时加载（alwaysApply / description 匹配 / 手动@或/）
3. 用我这句话测试会不会加载：「加一个抽奖」
4. 和 <另一个概念> 对比加载时机，不要扩展到 LLM/MCP
```

### B. 让任意代码库「按代码讲清楚」（可带走）

```text
【范围】只根据当前仓库源码，不讲外部最佳实践。
【任务】解释 <功能/模块/名词>。
【步骤】
1. 先 Grep/Glob 找到定义与引用，列出路径
2. 按调用链说明：入口 → 关键逻辑 → 数据/配置
3. 每个结论后面跟文件路径+关键代码（或行号）
4. 若仓库没有实现，明确写「未实现」，不要用别的项目例子顶替
【验收】我能指出该改哪个文件完成 <具体目标>
```

### C. 决定内容放 Rule 还是 Skill

```text
【范围】只做归类，不新建文件，不改代码。
【材料】我想约束/流程是：「…」
【标准】Always短约束→Rule；多步流程且仅某类任务→Skill。
【输出】表格：原文片段 | 归类 | 理由 | 建议文件名
【证据】对照本仓库已有 Rule/Skill 各举一条同类例子
```

## 反例对照（原问法 → 更好问法）

| 原问法 | 更好问法 |
| --- | --- |
| Skills、Rules 是什么 | 本仓库哪个是 Rule、哪个是 Skill？`alwaysApply` 和 Skill 的 `description` 各在什么时候把全文塞进上下文？用「加抽奖」和「改按钮颜色」各测一次 |
| 初期 UI 规范用 Skills 还是 Rules | 只做归类：把我下列 5 条 UI 约束标成 Rule/Skill，对照 `.cursor/rules` 与 `.cursor/skills`，不要科普 |
| Prompt/LLM 是什么 | 结合 Cursor：一次「加抽奖」对话里，Prompt 里大致有哪几段（用户话/Always Rule/Skill 全文）？LLM 指哪个可选模型？不要讲 RAG |
| Agent / MCP / Skills 都是什么，还有什么主流 AI 开发 | 拆成两次：先「本仓库有没有 MCP 配置文件」；再「一次对话里 Agent 调了哪些工具（读文件/终端）」——不要一次要行业全景 |

---

## 口诀

- **永远不能违反且要短** → 倾向 Rule（尤其 Always）  
- **某类任务才用的长步骤** → 倾向 Skill  
- **这一次的任务说明** → 聊天里的 Prompt  
- **真正生成回答的模型** → LLM  

提问时先锁 **范围 + 证据 + 对比上限 + 验收**，再问名词。
