# 用 AI 帮你加快写代码

这条路学的是：你仍负责功能和验收，AI 帮你改这个仓库里的页面和代码。

开发 Agent 产品（LLM、工具循环、MCP、评估）在 `cursor/前端转Agent学习清单.md`。做个人站功能时先读本文。

你已经会的前端判断仍然算数：页面对不对、路径能不能打开、手机能不能点，都由你看过再算做完。

---

## 1. 你要练的四件事

1. **把任务说具体**：改哪、改成什么样、怎样算做完。
2. **把相关文件放进这一轮**：打开文件、点名路径、贴上报错。模型只看这一轮能读到的材料。
3. **让现成约束生效**：本仓库每次对话都会带上 `.cursor/rules/personal-site.mdc`。加功能时说出「功能 / 抽奖 / 记事本 / 留言」，才会加载 `.cursor/skills/add-site-feature/SKILL.md`。
4. **自己看 diff 并打开页面**：它说做完了，你对一下改动和浏览器里的结果。

---

## 2. 你写下的那句话怎么写

你打的字只是 Prompt 的一部分。Rules、已加载的 Skill、打开的文件、历史，会和它拼在一起。你能直接控制的是任务说明。

一次只交一件事。写清这四样：

- **改哪里**：路径或文件，例如 `apps/web/src/home/`、`/personality/`
- **改成什么**：能看见的结果，例如「首页卡片多一张，搜索抽奖能出来」
- **保持什么**：例如「测评页逻辑不动」「存储键继续用 `hao.<id>.v1`」
- **怎样验收**：例如「手机宽度能点回首页」「直接打开 `/lottery/` 不用从首页进」

报错原样贴上，并写你点了什么。范围大时先让它列出要改的文件，你点头后再让它改代码。

同一句话里塞两个互不相关的功能，它容易改串。做完一件，再开下一件。

---

## 3. 用本仓库已有的 Rules 和 Skill

先读，再靠它们干活。

**Rules**（每次都在）：打开 `.cursor/rules/personal-site.mdc`。记住这几条就够用：

- 新功能是新路径，部署项目仍是 `cursor-personality-test`
- `/` 是首页，功能页是 `/<id>/`
- 首页卡片只来自 `apps/web/src/shared/catalog/index.ts`
- 浏览器里的数据键名是 `hao.<id>.v1`
- 每个功能要有 `功能文档.md`，里面要有「可拓展」

你发现它连续两次犯同一类错，就把那一句补进这条规则，或先改 `cursor/改进计划.md` 第 0 节再改规则里对应的一句。规则保持短。

**Skill**（加功能时才加载）：打开 `.cursor/skills/add-site-feature/SKILL.md`。你要新页面时，任务里写明「加一个功能」和类型（打开即用、笔记、留言）。做完后你按技能里的清单勾：

1. 有英文 `id` 和路径 `/<id>/`
2. 有 `apps/web/<id>/index.html` 和 `apps/web/src/<id>/`，并且登记了 Vite 入口
3. catalog 里有 name、aliases、tags、summary、path
4. 顶栏能回 `/`，地址栏直接打开该路径也能用
5. 有 `功能文档.md`，且「可拓展」四块写了内容

缺文档就还没做完。规格细节在 `cursor/改进计划.md`，需要时让它读第 0、5、9、10 节，不必每次把全文贴进对话。

---

## 4. 验收时看什么

按这个顺序看，比通读它的说明快：

1. **diff**：改动是否只在你点名的范围里。首页有没有绕过 catalog 写死卡片。
2. **路径**：新功能能否单独打开；返回首页是否还在。
3. **页面**：桌面和手机宽度各点一遍主路径。空状态、报错、返回，和主按钮一起看。
4. **数据**：若用了 `localStorage`，键是否是 `hao.<id>.v1`，有没有和测评或别的功能共用。
5. **文档**：`功能文档.md` 是否按当前页面写，而不是一份没实现的设计稿。

对不上就指出文件和期望，例如「`catalog/index.ts` 少了 aliases，搜索 MBTI 要能命中」。避免只回「不对，重做」。

---

## 5. 练习顺序

用这个站练，每步都你自己验收。

1. **改一句看得见的文案或样式。** 任务写明文件和验收（刷新后能看见）。练「一次一件事」。
2. **修一个小 bug。** 贴上操作步骤和报错，让它只改相关文件。你看 diff 是否顺手改了别的页面。
3. **读完 `personal-site.mdc` 再提一个会碰到红线的需求。** 例如给首页加入口。验收时检查它有没有改 catalog，而不是在首页写死链接。
4. **按加功能 Skill 做一个小工具页**（抽奖或笔记都可以）。你拿第 3 节的五条清单勾完，再在浏览器里直接打开该路径。
5. **把重复纠正写成一句规则。** 同一类错误出现两次以上，就收成 `personal-site.mdc` 里的一句话，或写进改进计划第 0 节。

第 4 步做完，日常用 AI 写这个站就够了。要自己做「会调工具的 Agent 产品」时，再读 `cursor/前端转Agent学习清单.md`。
