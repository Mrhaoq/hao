# 四年前端转 Agent：完整入门

面向：已经会做页面、状态、接口的前端，要从零搞清 Agent 相关名词，再动手。

若你要学的是「用 AI 帮你加快写代码」，读 `cursor/用AI加快写代码.md`。本文是「开发一个 Agent」时要懂的名词和结构。

后面每一节只用前面已经定义过的词。本仓库对照用现有文件，不另造一套规则或技能。

你已有的能力可以直接用上：组件边界 ≈ 工具边界，接口契约 ≈ 工具的参数说明，加载态 ≈ 执行过程，权限与环境变量 ≈ 密钥和沙箱。

---

## 1. LLM

LLM（大语言模型）就是模型。

输入一段文字，输出下一段文字，或输出「请调用某个工具」。它自己不记得这个仓库、不记得上次聊天，也没有技能文件。每次调用都只看这一次送进去的文字。

Cursor 里这次对话使用的模型，就是这一轮的 LLM。换一次对话、换一次调用，它就再从空白开始读输入。

---

## 2. Prompt

Prompt 是这一次调用送给 LLM 的全部文字。不是单指你打的那一句。

一轮里通常包括：

- Cursor 自带的系统说明（怎么用工具、怎么改代码）
- 下面要讲的 Rules
- 已经加载的 Skill 正文
- 对话历史
- 你的这句话
- 已经读过的文件
- 工具返回

LLM 没有单独的记忆文件。它只根据当前这包 Prompt 做决定。Prompt 变了，行为就变。

---

## 3. Rules

Rules 是写在 `.cursor/rules/*.mdc` 里的短约束。

文件开头可以写 `alwaysApply: true`，表示每次拼 Prompt 都放进去。本仓库是 `.cursor/rules/personal-site.mdc`。

Rules 只写每次都要守的边界，不写步骤。例如：只部署一个 Cloudflare Pages 项目、首页走 catalog、存储键用 `hao.<id>.v1`。修 bug、改样式、加功能都会带上这些句子。

冲突时，这条规则指向 `cursor/改进计划.md` 第 0 节关键词。Rules 是摘要，不是第二份规格。

---

## 4. Skills

Skills 是写在 `.cursor/skills/<名字>/SKILL.md` 里的操作单。

开头的 `description` 用来判断这次任务要不要加载；正文只在对上时进入 Prompt。本仓库是 `.cursor/skills/add-site-feature/SKILL.md`。它的 `description` 带上「功能、抽奖、记事本、留言、catalog」这类词，你说到这些，Agent 才去读正文。

Skills 只写会重复执行的步骤。例如：定 `id`、建入口、登记 catalog、写 `功能文档.md`。不要每个功能再写一个 Skill。

Rules 每次都在；Skills 任务对上才进 Prompt。

---

## 5. Agent

Agent 是包在 LLM 外面的循环，不是模型本身。

流程：拼 Prompt → 调 LLM → 若要工具就执行，并把结果放进下一轮 Prompt → 再调，直到回答你或该停。

关系用一句话收束：**Rules 和 Skills 都是 Prompt 的材料；Prompt 是 LLM 的唯一输入；Agent 负责反复拼 Prompt、调 LLM、执行工具。**

```
你的这句话
Rules（每次都放入）
Skill 的 description（用来判断要不要加载）
  → 对上则放入 Skill 正文
改进计划等长文（被读到才放入）
历史和工具结果
        ↓
这一轮 Prompt
        ↓
LLM 读 Prompt，输出文字或工具调用
        ↓
需要工具 → 运行时执行 → 结果进入下一轮 Prompt
任务结束 → 给你的回答
```

结束条件：做完、问用户、失败、步数上限。死循环常见于反复读同一文件、反复改同一处，必须能截断。工具失败后要决定：重试、换工具，还是把错误交回用户。

---

## 6. 长文档和入口

`cursor/改进计划.md` 是规格真源，不会自动进入每次 Prompt。几百行计划如果每次都塞进去，会挤掉代码和你的问题。

`AGENTS.md` 只告诉 Agent 先读哪几份：改进计划、Rules、加功能 Skill。它本身很短。

Skill 正文会写「先读改进计划第 0、5、9、10 节」。Agent 去读之后，读到的片段才进入后续轮次的 Prompt。

新原则先改改进计划第 0 节或第 13 节，再改 Rules 里对应的一句。不要再写第二份架构说明书，也不要为每个功能加 Skill、MCP 或钩子。这是改进计划第 15 节已经定下的。

---

## 7. 上下文窗口

Prompt 有长度上限，通常按 token 计。Rules、Skills、历史、打开的文件、工具结果，都占同一块窗口。

所以要分层：

- 每次都要守的短红线 → Rules
- 某类任务的步骤和模板 → Skill
- 完整规格、纠偏表、决策记录 → 长文档，按需读

工具返回要短、可判断。大段原文不要整段塞回 Prompt。历史变长后可以压缩，但路径、决定和未完成项不能丢掉。只有答案在仓库外或在一大堆文档里时才做检索，避免每次都搜全文。

---

## 8. 工具

LLM 只能发出调用请求。真正读文件、改代码、跑命令的是运行时。

工具要有参数说明：类型、必填、枚举、例子，以及何时用、何时不用、返回什么。一个工具做一件事。写文件、发请求、删数据和只读要分开。同一调用做两次，结果应可接受（幂等）。

前端的 `fetch` 契约在这里变成「LLM 可读的函数说明」。Agent 循环里，每一步是：LLM 决定调哪个工具 → 运行时执行 → 结果写进下一轮 Prompt。

---

## 9. 状态三层

前端的 `useState` / `localStorage` 不能当成 LLM 的记忆。三层不要混用：

| 层 | 放什么 | 典型位置 |
| --- | --- | --- |
| 本轮对话 | 当前任务、刚才的工具结果 | 会话里的 Prompt 历史 |
| 工作区 | 代码、计划、清单 | 仓库文件 |
| 跨会话 | 稳定偏好、项目约定 | Rules、`AGENTS.md` |

做到一半要能从仓库文件恢复。密钥和一次性日志不要写进跨会话那一层。

---

## 10. 编排

一个 Agent 包办一切会又慢又容易跑偏。编排是决定谁做事、做到哪、何时交给人。

单 Agent 跑稳后再拆：窄任务交给子任务，结果收成短结论再交回主循环。前台阻塞适合你正在等的结果；后台跑完再通知适合长任务。破坏性操作、密钥、范围不清时先问人。交接时最少带走：目标、约束、已查到的事实、不要重做的事。

---

## 11. 运行时协议

模型外面还有一层程序：发现工具、执行工具、流式输出、取消、权限。

协议是：LLM 发出调用 → 运行时执行 → 结果回到下一轮 Prompt。流式输出让你先看到字；中途可以取消；超时要停。沙箱决定哪些命令能跑、哪些路径能写、网络是否放开。

[MCP](https://modelcontextprotocol.io) 是把外部系统（浏览器、数据库、文档）接成标准工具和资源的协议。有真实外部系统要接时再上。本仓库按改进计划第 15 节，不为每个功能加 MCP 或钩子。

产品里的 Agent 入口不一样：编辑器里的 Agent、脚本里的 SDK、CI 里的无人值守 Agent，权限和「能不能问人」都不一样。

---

## 12. 评估和安全

页面可以用眼睛点一遍。Agent 每次路径可能不同，要靠痕迹判断它为什么这么做。

Trace 记录每一步：输入、选了哪个工具、参数、返回、耗时。失败常见于：选错工具、忽略 Rules、Prompt 被撑爆、幻觉路径、停不下来。改了 Rules 或工具后，用一小套固定任务重跑，看是否变差。步数、模型调用次数、大工具结果都会变成成本和延迟。

权限上：默认可读，写入和外部请求单独放开。密钥只在环境变量和运行时，不进仓库、不进前端、不进 Prompt 正文。强推、删库、清空目录必须人确认。网页、Issue、工具返回里夹带的「忽略之前的指令」当成不可信数据（提示注入）。不确定时停下来问，而不是补一套看起来能跑的操作。

---

## 13. 什么时候不用 Agent

先判断这件事该不该做成 Agent。

适合 Agent：步骤不固定、要读仓库再决定、中途要改计划。  
适合普通代码：输入输出固定、规则能写成函数、必须每次结果一样（表单校验、价格计算、路由）。

界面上要让人看见：当前在做什么、卡在哪、需要人做什么决定。内部推理不必整段甩给用户。

## 本仓库对照

- **LLM**：Cursor 里这次对话使用的模型
- **Prompt**：系统说明 + `personal-site.mdc` + 按需的 `SKILL.md` + 你的话 + 读到的改进计划片段 + 工具结果
- **Rules**：`.cursor/rules/personal-site.mdc`
- **Skills**：`.cursor/skills/add-site-feature/SKILL.md`
- **真源**：`cursor/改进计划.md` 第 0、9、15 节
- **入口**：`AGENTS.md` 指出先读哪几份
- **Agent**：读这些材料、改 `apps/web`、必要时再问你的那一层循环

副本还在 `cursor/.cursor/` 和 `cursor/AGENTS.md`。Cursor 实际读取的是仓库根下的 `.cursor/` 和 `AGENTS.md`。

---

## 建议顺序

1. LLM（第 1 节）——它只看这一次送进去的文字
2. Prompt（第 2 节）——分清「你打的那句」和「实际送进去的全部」
3. Rules（第 3 节）——打开 `personal-site.mdc`，看每次都会进 Prompt 的红线
4. Skills（第 4 节）——打开 `add-site-feature/SKILL.md`，看 `description` 和步骤清单
5. 真源怎么被读进来（第 6 节）——对照改进计划第 0、9、15 节和 `AGENTS.md`
6. 工具和 Agent 循环（第 5、8 节）——拼 Prompt、调 LLM、执行工具、把结果放回 Prompt
7. 上下文预算（第 7 节）——红线、步骤、长文档各进哪一层
8. 状态、编排、评估（第 9～13 节）——单 Agent 跑稳后再拆子任务；有外部系统再上 MCP

每学一块，用本仓库练：读一条 Rule、跟一次加功能 Skill、打开改进计划对应节，然后看 Agent 有没有按约束停住。
