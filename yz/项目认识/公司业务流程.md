# 颐挚业务 · 公司业务流程（四前端视角）

> 依据：`yishou-mobile` / `workcrm-web` / `organization-background` / `nurse-mini` 四份项目认识答案，以及接单池相关备忘。  
> 性质：从前端代码与模块划分**还原的业务全景**，非官方 SOP；不确定处标「未从代码确认」。  
> 系列入口：[项目认识 · 索引](./项目认识%20·%20索引.md)

---

## 一、公司在做什么

颐挚（品牌「颐挚科技」，主体线索含「上海颐寿健康科技有限公司」）面向 **家政 / 院内护工 / 居家护工 / 居家月嫂 / 陪诊** 等照护服务，把：

- **获客与销售**（线索 → 客户 → 下单）
- **履约与调度**（派单 / 接单池 / 排班 / 服务执行）
- **机构运营**（照护师、住院/免陪订单、财务、审批）
- **一线移动作业**（挚护通工作台、订单、学习、巡检）
- **多端支付与签约等 H5 能力**

串成一套 `*.yza.cn` 网关体系下的多端产品矩阵。

**一句话：** 用 CRM 卖单、用机构后台管人管钱、用挚护通干活、用 H5 容器承接支付/抢单/签约等嵌入场景。

## 二、角色 × 系统对照

| 角色（代码侧） | 主要系统 | 干什么 |
|----------------|----------|--------|
| 内部销售 / 管理 | `workcrm-web`（CRM） | 线索、客户、跟进、下单、派单、接单池、营销、工作手机风控 |
| 机构 / 医院用户 | CRM（部分）+ `organization-background` | 机构侧客户/订单协同；机构后台管照护师、住院/免陪、排班、财务、审批 |
| 管家 / 门店运营 | `nurse-mini`（挚护通） | 工作台：人员、订单、审批、开票结算、排班、巡检、学习 |
| 护理员 / 护工 / 接单方 | 挚护通 + `yishou-mobile` 抢单 H5 | 看单、接单、服务相关移动页 |
| C 端客户 / 家属 | 其它 C 端站 + `yishou-mobile`（支付、守护、协议等） | 支付、签约、守护设备、内容等（本仓多为嵌入页） |
| 督导 / 培训相关 | 机构后台 AI 督导 + H5 督导/培训模块 | 服务质控、日志、培训考试 |

统一身份：登录中心 `login-*.yza.cn`，Cookie / Token 名常见 `yilifeToken`，业务经 `gateway-*.yza.cn`。

## 四、主价值链（公司级端到端）

下面按「从获客到回款/结算」串主链。各环节旁标注主系统。

### 4.1 总览

```text
获客/营销 ──► 线索/潜客 ──► 跟进 ──► 客户 ──► 下单 ──► 支付
   │            │           │         │        │        │
  CRM营销     CRM线索     CRM跟进   CRM客户  CRM下单  H5支付
  内容访客     线索池      工作手机            │
                                              ▼
                                    待派单 / 进接单池
                                              │
                         ┌────────────────────┼────────────────────┐
                         ▼                    ▼                    ▼
                      CRM派单            接单池抢单             机构侧建单
                   （指定护理员）      CRM/H5/挚护通          （住院/免陪等）
                         │                    │                    │
                         └────────────────────┼────────────────────┘
                                              ▼
                                    待服务 → 服务中 → 完成
                                              │
                    ┌─────────────────────────┼─────────────────────────┐
                    ▼                         ▼                         ▼
                 排班/巡检                  督导质控                  续约/改价
               机构后台/挚护通            H5督导/AI督导              CRM订单详情
                    │                         │                         │
                    └─────────────────────────┼─────────────────────────┘
                                              ▼
                                    开票 / 结算 / 薪资对账
                                 挚护通 · 机构后台财务 · 审批
```

### 4.2 阶段说明

#### A. 获客与线索（主：CRM）

1. **营销触达**：落地页、文章、音视频、短信、智能外呼、微表单、个人名片、短链、抖音客户等（CRM `marketing-center`）。
2. **客资沉淀**：内容访客、客资录入、潜客；进入「我的线索 / 线索池」。
3. **跟进**：跟进记录、标签、阶段、星级规则（CRM 设置）；可用工作手机通话/短信/微信（风控与敏感词在 CRM `device-manage` / `record-manage`）。
4. **转化**：线索转客户；未转化可进公海，再被捞取（公海规则在 CRM 设置）。

**典型路径（CRM）：**  
登录 → 我的线索 → 跟进 → 转客户 → 客户管理 → 下单。

#### B. 下单与订单类型（主：CRM；机构侧另有住院/免陪）

CRM 订单类型（代码枚举）：

| 类型 | 场景概要 |
|------|----------|
| 院内护工 | 医院场景陪护 |
| 居家月嫂 | 居家母婴照护 |
| 居家护工 | 居家护理 |
| 陪诊 | 陪同就医等 |

订单状态主线（CRM）：**待支付 → 待派单 → 待服务 → 服务中 → 已完成 / 已取消**。

机构后台另管：**住院陪护订单、免陪订单**及业务套餐/站点/医院项目配置——偏院内履约与机构运营，与 CRM 销售单形成「销售侧 / 机构运营侧」双轨（交接细节未从代码完全确认）。

#### C. 支付（主：yishou-mobile）

支付页在 H5 容器（微信支付/支付宝等），由 CRM 或其它宿主带 Token 打开；支付完成后订单进入待派单等后续状态（状态推进以后端为准）。

#### D. 派单与接单池（CRM + H5 + 挚护通）

两条常见履约入口：

1. **指定派单**：订单详情内派单、联系护理员/管理员、改总价、修改订单、续约。
2. **接单池（抢单）**：
   - CRM：`grabOrder` 接单池（销售侧可转接单池 / 回归接单池）
   - H5：`yishou-mobile` 护士/员工抢单页（如 `/grabOrder/nurse/order`）
   - 挚护通：订单详情侧「回归接单池」等（接单租户场景）

含义：**订单可在「固定归属」与「池内抢单」之间流转**，用于跨租户/跨人接单协同（见备忘 `项目问题/26.6.23-接单池3.0.md`）。

#### E. 服务执行（挚护通 + 机构后台 + H5）

| 动作 | 系统 |
|------|------|
| 一线看单、处理订单、开票结算入口 | 挚护通 |
| 人员/护工档案、报名、合同、授权 | 挚护通 |
| 排班、日历、工作日志 | 挚护通 + 机构后台排班 |
| 服务巡检 | 挚护通 |
| 照护师主数据、能力模型、服务小组 | 机构后台 |
| 督导日志 / AI 小结 / 服务反馈 | H5 `supervisor` + 机构 `aiSupervisor` |
| 培训考试 | 挚护通学习 Tab + H5 `train`/`learning` |

#### F. 财务闭环（机构后台 + 挚护通）

- **机构后台**：薪资、对账、开票、订单/护工支出统计；对账可跳住院订单详情。
- **挚护通**：收入、结算、开票相关页。
- **审批**：机构后台审批/待办/发票袋；流程常嵌 `wflow-web`；挚护通有 OA/审批分包。

#### G. 续约与售后（CRM + H5）

- CRM 订单详情：续约、改价、状态变更。
- H5：物流/售后物流、协议/电子签、保险等内容页可嵌入。

## 五、分系统关键流程（更细）

### 5.1 CRM：`线索 → 客户 → 订单 → 派单/池`

```text
营销物料 / 外呼 / 表单
        │
        ▼
  潜客 / 我的线索 / 线索池 ──跟进──► 转客户 ──► 我的客户 / 公海
                                      │
                                      ▼
                                   下单弹窗
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                     待支付订单                 （其它来源单）
                          │
                          ▼ 支付（常跳 H5）
                     待派单订单
                          │
            ┌─────────────┼─────────────┐
            ▼             ▼             ▼
         指定派单      转接单池      回归接单池
            │             │             │
            └─────────────┴──────► 待服务 / 服务中
                                      │
                                      ▼
                                 完成 / 取消 / 续约
```

配套能力：团队组织与角色权限、数据中心（客户/线索/营销分析）、工作手机风控。

### 5.2 机构后台：`人 → 单 → 班 → 钱 → 审`

```text
照护师入职/档案/证书/能力/小组
              │
              ▼
   业务配置（套餐·站点·医院项目）
              │
    ┌─────────┴─────────┐
    ▼                   ▼
住院陪护订单         免陪订单
    │                   │
    └─────────┬─────────┘
              ▼
           排班调度
              │
              ▼
     服务过程（督导/评价/巡检协同）
              │
              ▼
     薪资 · 对账 · 开票 · 财务统计
              │
              ▼
         审批流 / 待办 / 发票袋
```

与 CRM 的关系：CRM 偏「卖与派」，机构后台偏「院内/机构履约与财务」；域名配置可见互跳 CRM / 挚护通 H5。

### 5.3 挚护通：一日作业闭环

```text
登录/静默登录/授权
        │
        ▼
     工作台（按权限菜单）
        │
   ┌────┼────┬────┬────┬────┐
   ▼    ▼    ▼    ▼    ▼    ▼
 人员  订单  审批  排班  巡检  学习
 报名  开票  OA   日历       培训
 合同  结算
        │
        ▼
   消息中心 / 我的（收入等）
```

角色差异：订单 Tab 会按 `rolesId` 跳到不同真实订单页（管家 vs 护理员等）。

### 5.4 H5 容器：被谁打开、办什么事

```text
宿主 App / 企微·微信小程序 / 浏览器
        │  带 _token / accessToken 等
        ▼
  yishou-mobile 落地具体路由
        │
   ┌────┼────────┬────────┬────────┬────────┐
   ▼    ▼        ▼        ▼        ▼        ▼
 支付  抢单    订单详情  电子签   守护设备  督导培训
              CRM下单页  人脸认证  告警报告  AI聊天等
```

特点：**不是独立主站**，而是业务页聚合仓；默认落地与访客 WiFi 等相关，核心价值是「各端共用同一套 H5 业务页」。

## 七、关键业务专题

### 7.1 接单池

- **目的：** 订单在租户/销售归属与「池」之间流转，支持抢单履约。
- **入口：** CRM 接单池页；CRM/挚护通订单详情「转/回归接单池」；H5 护士/员工抢单。
- **白名单类接口线索：** 如 `organization-admin/admin/transferOrder2PoolStatus`（见接单池备忘）。

### 7.2 人员供给

```text
招聘/面试/体检/考核（机构后台）
        │
        ▼
照护师/护工档案（机构后台 + 挚护通服务人员）
        │
        ▼
能力 · 小组 · 排班 · 派单/抢单可用
```

### 7.3 质控与培训

- 服务中：巡检（挚护通）、评价/反馈（机构）、督导日志与 AI 小结（H5/机构）。
- 能力提升：挚护通「学习」Tab、H5 培训/考试。

### 7.4 合规与风控（销售侧）

工作手机：激活、微信绑定、通话/短信/位置、敏感词与敏感操作、财务敏感——约束销售触客过程，与线索跟进强相关。

## 九、读代码时怎么顺着流程走

| 你要搞清的事 | 建议顺序 |
