# 04 · 详情头部操作详解

源码：[`detail/index.vue`](../../src/views/order/detail/index.vue) 及 `component/*`

返回：[总目录](./README.md) · [03 状态矩阵](./03-详情打开与状态矩阵.md)

每个按钮格式：**条件 → 交互 → 组件/函数 → 接口 → 副作用**。

---

## 1. 刷新

- **条件**：始终
- **交互**：`refersh`；`base` tab 全量 `getDetail` + 子模块刷新；`evaluation` 刷评价
- **副作用**：无

---

## 2. 回归接单池

- **条件**：`showReturnToPool`：`orderStatus===2` 且 `grabbers.length === maxGrabCount`
- **交互**：`handleReturnToPool`
  - 若 `grabRecords` 不存在全员 `status∈[3,5]` → alert：需先反馈全部公司不可派原因
  - 否则确认 → 调用回归
- **接口**：`api73020` → `POST /organization-admin/poolOrder/returnToPool`
- **副作用**：刷新详情

接单池列表页有同类逻辑（见 [06](./06-接单池与抢单.md)）。注意展示用 `grabbers`、校验用 `grabRecords`，字段不一致时需两边数据都齐。

---

## 3. 转接单池

- **条件（详情外层）**：`record.showTransferGrabPool`
- **组件内兜底**：`showTransferGrabPool` 为 boolean 则用之，否则 `orderStatus===2`
- **交互**：确认弹窗 → 提交
- **组件**：`customer-turn-btn.vue`
- **接口**：`api69160({ orderId })` 订单转移进池
- **副作用**：`handleTransferGrabPool`：`showTransferGrabPool=false`，`isGrab=true`，`deleteOrder?.(row)`（列表移除/刷新）

列表行更多里也可转池（需 `authTransfer` / `showTransferGrabPool`）。

---

## 4. 联系管理员 / 联系医疗护理员

- **条件**：`showOperation && !isGrab` 且对应列表非空
- **列表**：管理员 `api61631({ hospitalId })`；护理员 `api61799({ orderId, page… })`
- **交互**：下拉选人 → IM 账号 `api59615` → 发任务 `api57857`（taskType 4）
- **副作用**：成功 toast，可 `refersh`

接单池态不展示（减少与指派公司链路混淆）。

---

## 5. 改总价

- **组件**：`edit-price-btn.vue`
- **显示**：`orderStatus∈[2,3,4]` 且 `maxPrice = ceil(totalFeeAmount/100) > 0`
- **点击**：
  - 已有 `orderDiscountRecordDTOS[0].processId` → `emit('amountProcess')` → 打开审批抽屉
  - 否则打开减免弹窗，金额元→分 `*100`
- **接口**：`api61887`
- **副作用**：`@confirm` → `refersh`；财务区减免编辑同源逻辑（见 [05](./05-详情信息区块.md)、[08](./08-支付合同审批续约.md)）

---

## 6. 修改订单

- **组件**：`edit-combo-btn.vue` → `EditOrderInfo.open(3, row)`
- **显示**：`orderStatus∉[8,9]`
- **点击**：
  - 有 `updateOrderServiceTimeApprovalDTO.processId` → `viewApproval` 看审批
  - 否则打开改单弹窗（可能影响收费，系统重算）
- **改单内换人 `addCarer`**：
  - `unref(isGrab) || unref(isGrabOrg)` → **AssignerDrawer**
  - 否则 → 阿姨列表（`sourceType=changeAunt`）
- **关键接口**（改单场景）：详情 `api61783`；改套餐等 `api11359` / `api73460`；派单相关 `api11199` 等
- **副作用**：`@confirm` → `refersh`

---

## 7. 派单（两条完整链路）

### 7.1 接单池 / 抢单态（`isGrab=true`）

```text
详情头 SendOrderBtn raw=true + 外层 @click=sendOrders
  → feedbackInfoRef.sendOrders()
  → AssignerDrawer
  → 确认派单
  → api61783 + api61759 组装（抽屉内）
  → api71632 订单池派单
  → emit assign → 刷新 AssignInfo；关抽屉 → 父 refersh
```

- 按钮显示：`isGrab` 时 `send-order` 的 `show` 恒为 true
- 反馈：抽屉 `@feedback` → `FeedbackDialog` → `api71420`；列表 `api71424`

### 7.2 普通态（`isGrab=false`）

组件：`send-order.vue` 自身 `handleClick`

```text
raw → return（不处理）
isGrabOrg → AssignerDrawer（同抢单机构派单）
否则：
  api61759 查服务单
    ├─ 有 data →「是否更换护理员」→ 确认后开阿姨列表
    └─ 无 → 直接开阿姨列表
  选人 sendOrderConfirm
    → api61783 取末条子单时间
    → api61751 orderMultiDistributeV2
    → 成功弹窗 → emit confirm → refersh
```

- 按钮显示：`exceptionOrderList` 含「未派单」
- 列表页另有 `orderTag!==1` 才挂载组件

### 7.3 对照

| | 普通 | 接单池 / isGrabOrg |
|--|------|-------------------|
| UI | 阿姨列表 | AssignerDrawer（公司） |
| 提交 | `api61751` | `api71632` |
| 详情头绑定 | `@confirm=refersh` | `raw` + `sendOrders` |

---

## 8. 续约

- **模板条件**：`orderStatus!==9`
- **组件内更严**：`orderType!==1`；状态∈`[2,3,4,8]`；已完成且结束时间+6h&lt;now 隐藏
- **组件**：`customer-follow-btn` → `renewal.vue`
- **提交**：见 [08](./08-支付合同审批续约.md) → `updateRenewalOrderPackageV2`
- **副作用**：`@confirm` → `refersh`

---

## 9. 结束服务

- **条件**：`orderStatus===4`
- **交互**：确认 → `onEndServiceConfirm`
- **接口**：`api11355`
- **副作用**：`refersh`

---

## 10. 取消服务

- **条件**：`orderStatus∈[1,2,3,4]`
- **交互**：
  - 已有 `cancelOrderApprovalDTO.processId` → 打开审批
  - 否则弹窗选取消原因（`api5115`）
  - 是否走审批：`isApproval`（未付且 2/3/4，或已付且 2/3 等逻辑）→ `api61863`，否则直接 `api853`
- **副作用**：`refersh`

> 实现细节：注意 `isApproval` 是否正确取 `.value`（历史坑，排查时看 Network 实际打的是审批还是直接取消）。

---

## 11. 审批抽屉（共用）

- **组件**：`approvalDrawer.vue` → `open(processId)`
- **接口**：wflow `GET /wflow/wflow/process/progress/{processId}/node_0`
- **触发**：改价、改服务时间、取消服务审批中
