## 1. 页面定位

接单池是**销售侧管理已进池订单 / 抢单公司**的工作台，与「订单管理」列表分离。

- 建单：固定 `isOrderPool: true`，`operation=HOME_ORDER`
- 打开详情：强制池态（`isGrab=true`）

---

## 2. `ensureDetailQuery`

```ts
router.replace({
  query: { ...route.query, isGrab: "true", showOperation: "true" },
});
```

调用点：`handleView`、`handleOpenOrderDetail`、`onMounted`。

再配合：

```ts
detailRef.open(row, true)
// 或
detailRef.open(res.data, isOrderPool ?? true)
```

即使 Detail setup 只读一次 query，显式第二参也能保证池态。

## 5. 回归接单池

与详情头逻辑一致，列表侧条件略不同表述：

1. **按钮/入口条件**：`grabRecords.length === maxGrabCount`（列表）或详情 `grabbers.length === maxGrabCount` 且待派单
2. **可执行条件**：每条记录 `status ∈ [3, 5]`（已反馈不可派等）
3. 否则 alert：需先反馈全部家政公司不可派原因
4. 确认 → `api73020({ orderId, userId })` → `POST /organization-admin/poolOrder/returnToPool`

## 6. 与线索「选接单池下单」汇合

```text
线索/跟进 resolveOrderPoolPosition → isOrderPool=true → 建单
  → OPEN_ORDER_DETAIL { isOrderPool:true }
  → Detail isGrab=true → api71408
  → 派单 AssignerDrawer → api71632
```

与本页打开已有池单的行为对齐。差异：本页列表本身就是池数据源；线索侧订单可能同时出现在订单管理，但详情必须以 `isGrab` 打开才正确。
