## 1. 统一打开入口

```ts
detailRef.open(row, isGrabValue?)
```

流程：`resolveIsGrabFlag` → 写 `orderId` → `visible=true` → `getDetail()` → 拉管理员/护理员/取消原因。

`provide('isGrab', isGrab)`（**ref**，子组件可响应更新）。

---

## 2. `resolveIsGrabFlag(row, isGrabValue)`

优先级（高 → 低）：

1. 显式第二参 `isGrabValue !== undefined && !== null` → `!!isGrabValue`
2. `row.isOrderPool != null` → `!!row.isOrderPool`
3. `row.poolOrderStatus` 有值 → `Number(poolOrderStatus) !== 0`
4. `props.isGrab || route.query.isGrab === 'true'`

### 各入口如何传

| 入口 | 调用 |
|------|------|
| 订单列表 | `open(row)` 或 `open(data, isOrderPool)` |
| 接单池 | `ensureDetailQuery` 后 `open(row, true)` / `open(data, isOrderPool ?? true)` |
| 我的线索 / 客户跟进 | `open(data, isOrderPool)`（事件携带） |
| 跟进订单情况面板 | `open(row, poolOrderStatus != 0)` |

---

## 3. `showOperation`

```ts
route.query.showOperation === 'true' || props.showOperation  // 默认 true
```

| 值 | 行为 |
|----|------|
| true | 展示改价/改单/派单/续约/结束/取消等 |
| false | 隐藏操作区；合同/支付等空态或只读（公共池） |

注意：`getDetail` 分流里用的是 **`props.showOperation`**，不是带 query 的 computed。

---

## 4. 详情 API 分流 `getDetail`

| 条件 | API | URL 语义 |
|------|-----|----------|
| `isGrab===true` | `api71408({ orderId, source:0 })` | 抢单/接单池详情 |
| `!isGrab && props.showOperation` | `api61783({ orderId })` | 普通可操作详情 |
| `!isGrab && !props.showOperation` | `api69180({ orderId })` | 公共池只读详情 |

回填：`orderTypeName` / `orderStatusName` / `leaderSourceName` + `...res.data`。
