# 开书

口径以工作台根目录 `测书思路.md` 为准。改开书需求先改总纲并补修订记录，再按 `.cursor/skills/ce-shu-lian-dong/SKILL.md` 改齐关联文件，不要只改本技能。

## 步骤

1. 确认一句方向。方向不清就先问，不写正文。
2. 在 `D:\A-work\hao\测书工作台\文稿\` 下新建 `<编号-书名>\`。
3. 写齐这些文件后再停：
   - `设定.md`：用标题区分「标题 / 标签 / 主题 / 简介 / 人物 / 世界 / 大纲 / 伏笔 / 关系 / 地点势力 / 道具 / 前情」（关系、地点势力、道具可空；大纲每阶段可列里程碑）；简介约 60 字（50～70 字）。人物写欲望、把柄、不能做的事；世界只写本卷会用到的规则；大纲写 0–3 / 3–8 / 8–12 / 12–20 / 20–26 / 26–30 万，文末写「数据好则续」「数据差则短收尾」；伏笔每条标 `must` 或 `drop`，必收的写明最晚回收字数；26 万后不再新增 must
   - `正文/全书.txt`：正文未开写时只放一句说明
4. 不要再拆 `设定/`、`大纲/`、`伏笔/` 多个文件。读到旧拆分文件就并进 `设定.md` 并删掉。
5. 正文每章建议 1800 到 2500 字。超出或不足优先改这一章；工作台贴回只提示字数、不拦提交。
6. 提示词交给用户贴进豆包。不打开浏览器，不自动发送。用户贴回后，再写入对应文件。
7. 新开框架默认「候选」；只有进入正文生产才占在产槽，同时在产最多 3 本。

## 30 万字首轮裁决

- 0–3 万字：读者知道主角要什么、阻碍是什么、失败代价是什么
- 3–8 万字：加压蓄力，不提前写完高潮
- 8–12 万字：有一次明确兑现
- 12–20 万字：确认本卷对手与因果链
- 20–26 万字：锁定结局路径，停止新增 must
- 26–30 万字：核心事件闭环、主要真相揭晓、本卷对手有结果。更高层谜可以留
- 数据好：继续按需加字数（默认 10 万、最少 5 万），先贴回续写段大纲；数据差：6～10 章交代后果和去向后停；未验证：再观察

## 不合格 / 合格

```text
不合格：只有书名就写第 1 章；简介不是约 60 字；设定大纲伏笔拆成多个文件；一章 800 字或 6000 字；30 万字时真凶还没出场
合格：一本书一份设定.md 用标题区分各块，简介约 60 字，第 1 章 1800 到 2500 字，30 万字处核心事件已闭环、本卷对手有结果；更大的谜可以留
```
