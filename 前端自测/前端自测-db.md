## 一、前端完整自测流程（按开发阶段划分）

前端自测不是 “写完代码随便点两下”，而是贯穿开发全周期的递进式校验，核心目标是在提测前消灭绝大多数低级 bug、边界 bug 和阻断性问题。

### 阶段 1：需求评审后、开发启动前 — 测试点前置梳理

- **动作**：对照 PRD、UI 设计稿、接口文档，拆解当前需求的所有功能点、校验规则、异常分支，形成一份简易自测清单。
- **核心价值**：提前对齐规则边界，避免开发到一半才发现对需求理解偏差；同时把边界条件、异常场景提前列出来，防止写完代码后遗漏。
- **梳理维度**：正向主流程、校验规则、边界极值、异常分支、权限限制、交互反馈。

### 阶段 2：开发过程中 — 组件级 / 单元级即时自测

- **动作**：写完一个独立组件、一个功能块就立刻自测，不要等整个页面全部完成再统一测试。
- **覆盖内容**：
  1. 组件所有 props 入参场景（必填 / 可选 / 默认值 / 异常值）
  2. 组件内部状态切换（禁用 / 启用、展开 / 收起、加载 / 空闲）
  3. 事件回调触发时机与传参正确性
- **优势**：问题定位快、修改成本低，避免后期联调时小问题堆积。如果团队有单测规范，在此阶段补充单元测试。

### 阶段 3：功能开发完成 — 正向主流程全链路自测

- **动作**：模拟普通用户的完整操作路径，从头到尾走通核心业务链路。
- **示例**：新增表单→填写合法内容→提交成功→跳转列表→查看新增数据→进入详情→编辑修改→保存返回→列表数据同步更新。
- **核心要求**：必须使用真实接口联调，不能全程依赖 mock 数据。mock 只能覆盖开发阶段，真实接口的字段差异、返回结构是高频 bug 来源。

### 阶段 4：深度自测 — 边界、异常、反向场景

这是前端自测最核心的环节，80% 的线上低级 bug 都出自这个环节的遗漏。跳出 “正常用户” 视角，用 “破坏式” 思路测试所有非理想场景。

### 阶段 5：体验与兼容性自测

- **动作**：核对 UI 还原度、交互流畅度、多端 / 多浏览器兼容性。
- **覆盖范围**：目标分辨率适配、主流浏览器兼容（Chrome/Edge/Safari）、键盘可访问性、加载体验、动画过渡。

### 阶段 6：提测前 — 回归与最终校验

1. 修复所有自测发现的问题后，回归主流程和修改点，确认修复无误且未影响其他功能；
2. 代码自查：ESLint 校验通过、删除调试用的`console.log`/`debugger`、清理无用代码和注释；
3. 最终确认：所有需求点全部实现，无遗漏、无阻断性问题。

## 二、前端自测的核心通用重点

无论什么功能模块，都可以从以下 7 个维度全覆盖自测：

1. **需求一致性**：逻辑、文案、样式完全匹配 PRD 和 UI 稿，不自行删减规则或修改交互。
2. **边界与极值**：所有限制条件的临界值、最大值、最小值、空值、全量值，是 bug 最高发的区域。
3. **异常容错性**：接口失败、网络异常、非法输入时，页面不能白屏、崩溃、无响应，要有明确降级提示。
4. **操作反馈性**：用户每一次操作都要有即时反馈（加载态、成功 / 失败提示、按钮状态变化），不能让用户感知 “操作没生效”。
5. **数据一致性**：前端展示与接口返回一致；增删改后关联页面数据同步更新；缓存与实时数据无冲突。
6. **安全与权限**：无权限的按钮 / 页面要隐藏 / 拦截；敏感信息（手机号、身份证）需脱敏；用户输入需做转义防范 XSS。
7. **性能稳定性**：频繁操作不卡顿、接口不重复请求、大数据列表滚动正常、内存无异常增长。

## 三、常见功能模块自测示例与解释

### 1. 输入表单（最高频、规则最多的模块）

表单是前端最基础也最容易出细节 bug 的模块，必须覆盖校验、交互、提交、回显全链路。

表格







| 自测分类 | 具体自测项                                                   | 自测解释与风险点                                             |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 必填校验 | 1. 所有必填项为空直接提交，是否弹出对应提示2. 提交时是否自动定位到第一个校验不通过的项3. 纯空格 / 纯换行输入，是否判定为空值 | 很多前端仅做提交时校验且不处理纯空格，会导致后端收到空字符串脏数据；无定位提示会让用户无法快速找到错误 |
| 格式校验 | 1. 手机号 / 邮箱 / 身份证 / 网址等，合法 / 非法值是否正确判定2. 数字输入框：负数、小数位数、0 值、超大数值是否符合规则3. 中文输入法未选词时（composition 阶段），是否误触发校验 | 格式正则不严谨会导致合法数据被拦截、非法数据流入后端；中文输入法误触发是高频体验 bug |
| 边界值   | 1. 最大字符限制：刚好等于限制值、超出限制值，是否正常拦截 / 截断2. 超长文本粘贴，是否符合长度限制3. emoji、特殊符号、全角字符、生僻字是否能正常输入和展示 | 超长文本提交可能触发后端参数长度限制报错；特殊字符编码处理不当会导致展示乱码或接口异常 |
| 安全注入 | 1. 输入 `<script>alert(1)</script>` 等 XSS 脚本，提交后回显是否被转义2. 输入 SQL 注入字符，是否正常处理不报错 | 未做转义的输入会造成 XSS 安全漏洞，尤其在备注、评论、富文本场景中风险极高 |
| 表单联动 | 1. 级联选择（省→市→区）：上级修改后下级是否重置，选项是否匹配2. 单选控制显隐：隐藏的输入框是否清空值并移除校验3. 计算联动：输入数量和单价，总价是否实时正确计算 | “隐藏字段仍参与校验” 是最常见的表单 bug，会导致表单无法提交；级联不清空会产生数据不匹配的脏数据 |
| 提交逻辑 | 1. 提交过程中按钮是否禁用，防止重复点击重复提交2. 提交失败时，是否保留用户已填写内容3. 提交成功后，是否正确清空表单 / 跳转 / 刷新列表4. 回车快捷键是否能正常提交 | 重复提交会造成后端重复生成数据，属于典型低级 bug；提交失败清空内容是严重体验问题 |
| 编辑回显 | 1. 进入编辑页，所有字段回显是否与详情页一致2. 禁用 / 只读字段是否真的无法修改3. 回显后修改提交，请求参数是否正确 | 回显遗漏、禁用字段可修改会直接导致数据异常，尤其涉及金额、状态的字段 |

### 2. 列表查询与筛选

表格







| 自测分类   | 具体自测项                                                   | 自测解释                                                     |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 空数据场景 | 1. 接口返回空数组，是否展示空状态组件2. 筛选无匹配结果时，是否正确展示空状态 | 空数据无处理会导致页面空白，属于基础体验缺失                 |
| 分页逻辑   | 1. 第一页、最后一页、跳转指定页，数据是否正确2. 每页条数切换后，是否重置到第一页3. 当前页数据全部删除后，是否自动回退到上一页4. 总条数、总页数计算是否正确 | 分页边界处理不当，会出现页码越界、删完数据页面空白的问题     |
| 筛选查询   | 1. 多条件组合筛选，请求参数拼接是否正确2. 点击重置，是否清空所有条件并刷新列表3. 筛选后切换页码，筛选条件是否保留4. 输入特殊字符 / 超长关键词查询，是否报错 | 重置不清空、筛选后分页未重置是高频 bug；关键词特殊字符可能导致接口查询异常 |
| 加载体验   | 1. 请求过程中是否有 loading / 骨架屏，避免页面空白2. 快速多次点击查询，是否做防抖，是否只展示最新结果3. 接口报错，是否展示错误提示和重试按钮 | 无防抖会导致多次请求乱序，出现旧数据覆盖新数据的闪烁问题     |

### 3. 弹窗 / 抽屉 / 浮层

- 打开 / 关闭动画正常，遮罩层正确显示；点击遮罩、关闭按钮、ESC 键均可关闭；
- 弹窗打开时，禁止背景页面滚动，避免出现双滚动条；
- 弹窗内有表单时，关闭后再打开，表单是否重置为初始状态；
- 弹窗内提交成功后，是否自动关闭并刷新父页面数据；
- 多层弹窗嵌套时，层级顺序正确，关闭时仅关闭当前层。

### 4. 文件上传与下载

- 文件类型 / 大小限制：不符合要求的文件是否前端提前拦截并提示；
- 上传过程：是否有进度条；上传中是否可取消；上传失败是否有重试入口；
- 异常场景：网络中断、文件损坏、空文件上传，是否有友好提示；
- 下载功能：文件名、格式是否正确；大文件下载是否有提示；下载失败是否告知用户。

### 5. 数据表格操作

- 排序：点击表头升序 / 降序 / 取消排序，状态与请求参数是否一致；
- 批量操作：全选 / 全不选 / 半选状态是否正确；跨页选择是否按业务规则保留；
- 行内编辑：编辑态切换正常；保存 / 取消生效；校验规则正常触发；
- 删除操作：是否有二次确认弹窗；删除成功后列表是否实时刷新。

### 6. 路由与页面跳转

- 正常跳转：菜单、按钮跳转后，路由地址、页面内容、参数是否正确；
- 页面刷新：刷新当前页，数据是否正常加载，路由参数是否丢失；
- 浏览器前进 / 后退：页面状态是否同步更新，避免出现数据不更新；
- 权限校验：直接地址栏输入无权限路由，是否被路由守卫拦截；
- 404 兜底：输入不存在的路由地址，是否正确展示 404 页面。

## 四、提测前最终必过自查清单

1. 代码层面：ESLint 无报错、无遗留`debugger`/ 调试日志、无大量注释掉的无用代码
2. 主流程：核心业务链路可完整走通，无阻断性问题
3. 异常场景：接口报错、空数据、网络异常时页面不白屏、有明确提示
4. 交互体验：所有操作有反馈、按钮状态正确、无重复提交风险
5. 兼容性：目标浏览器、分辨率下页面无错乱、功能可用
6. 安全合规：敏感信息脱敏、无越权操作、输入有基础 XSS 防护
