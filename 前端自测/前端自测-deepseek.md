## 一、前端自测的标准流程

可以遵循 **“需求 → 开发 → 验证 → 修复 → 再验证”** 的闭环：

1. **需求理解与用例梳理**
   - 读懂原型、需求文档，明确正常流程、异常流程、边界条件。
   - 把关键点列成简单的 checklist（脑图或文档都可以）。
2. **本地开发 + 即时自测**
   - 每完成一个组件/模块，就用本地的 mock 数据跑一遍核心流程。
   - 检查控制台是否有报错、警告（如你的 Sass 弃用警告）。
3. **功能完整性自测**
   - 按照 checklist，逐条“假装自己是用户”去操作一遍，覆盖 **正常 + 异常 + 边界** 场景。
   - 包含接口联调（如果有后端），观察请求/响应是否正确。
4. **UI/交互还原度检查**
   - 对照设计稿，逐像素比较（可借助 Figma 标注、PxCook 等工具）。
   - 注意不同屏幕尺寸、浏览器下的表现。
5. **回归自测**
   - 修复 bug 或代码变动后，把相关联的功能再快速跑一遍，避免改 A 坏 B。
6. **提交前的整理**
   - 清理 `console.log`、无用注释、测试代码。
   - 运行 lint、类型检查，确保代码风格统一。
   - 更新必要的自测报告或填好提测单。

------

## 二、自测的通用重点维度

无论什么功能，都可以从这几个角度去“找茬”：

- ✅ **功能正确性**：是否符合需求，数据流转是否无误。
- 🎨 **UI 还原度**：字体、颜色、间距、图标、动效与设计稿一致。
- 🧩 **交互体验**：操作反馈（加载、成功/失败提示）、页面跳转、手势/快捷键。
- 🧪 **边界条件**：空数据、超长文本、极大/极小数值、临界时间。
- ⚠️ **异常处理**：网络断开、接口超时/报错、权限不足等情况下的表现。
- ⚡ **性能表现**：列表渲染是否卡顿、图片是否懒加载、接口是否重复请求。
- 🌐 **兼容性**：主流浏览器、操作系统、移动端设备。
- 🔒 **安全性**：用户输入过滤（XSS）、敏感信息加密、CSRF 防护等。

## 三、按常见功能场景的自测示例

### 1. 输入表单（最常见的自测重灾区）

**场景**：包含文本输入、数字、手机号、邮箱、密码、下拉选择、单选/多选、日期选择等，还有表单验证、提交、重置。

**自测检查点**：

| 类别     | 具体检查项                                                   |
| :------- | :----------------------------------------------------------- |
| 基本交互 | 可正常聚焦、输入、失焦；placeholder 正确显示；键盘类型匹配（数字键盘、电话键盘等） |
| 输入限制 | 最大/最小长度、禁止输入特殊字符、输入法 emoji 能否通过校验、前后空格是否自动去除 |
| 数据校验 | 必填项为空时提示清晰；邮箱、手机号等格式校验准确；自定义校验规则（如两次密码一致） |
| 边界值   | 数字输入：0、负数、小数位数、超大数值；文本域：换行、超长英文单词破坏布局 |
| 异常操作 | 复制粘贴、拖拽文本、浏览器自动填充（黄色背景）、输入后立刻点击提交 |
| 表单状态 | 提交按钮的禁用态（校验不通过时不可点）、提交中 loading 态、防重复提交 |
| 数据回填 | 编辑场景下，表单是否正确回显后端数据；密码框不回填；日期格式与显示一致 |
| 重置按钮 | 点击重置，所有字段恢复默认值或初始值，验证错误信息消失       |
| 安全性   | 输入 `<script>alert(1)</script>` 看是否转义；富文本输入需 XSS 过滤 |

**示例说明**：
测试“手机号输入框”，你需要尝试：

- 输入 10 位数字 → 提示格式错误；
- 输入 11 位数字但第1位不是 1 → 提示；
- 粘贴带空格的号码 → 程序是否自动 trim；
- 获取验证码按钮的倒计时逻辑、重新发送是否重置；
- 键盘弹起时页面是否上移、不会遮挡按钮。

### 2. 列表及数据展示

**常见场景**：订单列表、消息通知、搜索结果。

**自测重点**：

- **空状态**：无数据时显示友好的占位图/文案。
- **加载中**：骨架屏或 loading 动画正常，不会在数据未到时就显示“暂无数据”。
- **分页/滚动加载**：下拉刷新、上拉加载更多，最后一页不再继续请求，没有重复数据。
- **排序/筛选**：切换不同条件，数据刷新且保留筛选状态。
- **数据更新**：单条删除/修改后列表即时刷新，不整页重载。
- **长列表**：虚拟列表是否导致白屏，快速滚动时图片加载是否流畅。

------

### 3. 弹窗 / 对话框

**自测重点**：

- **打开/关闭**：点击触发按钮弹出，关闭按钮、蒙层、返回键、ESC 键均能关闭。
- **数据交互**：弹窗内表单提交成功后关闭并刷新父页面，失败则留在弹窗显示错误。
- **层级遮罩**：多个弹窗嵌套时，层级正确；滚动弹窗时，底层页面不随动（滚动穿透）。
- **异步关闭**：弹窗内有异步操作时，确认按钮 loading，避免双击产生多个请求。

------

### 4. 文件上传

**自测重点**：

- 文件类型限制（jpg/png/pdf）、大小限制（超过时前端提示）。
- 单文件/多文件数量限制。
- 上传进度条显示、取消上传、上传失败后重新上传。
- 图片预览正确，压缩/裁剪功能正常。
- 上传过程中关闭页面，下次进入是否可以恢复。

------

### 5. 登录 / 权限控制

**自测重点**：

- 不同角色（普通用户、管理员）看到的菜单和按钮不同。
- Token 过期后，接口调用返回 401，前端自动跳转登录页或刷新 token。
- 未登录直接访问需要权限的页面，重定向到登录页，登录后回到原页面。
- 多 tab 登录状态同步。

------

### 6. 响应式 / 多端适配

**自测重点**：

- 使用 Chrome DevTools 切换设备模式，检查布局错乱、横向滚动条、字体过小。
- 刘海屏、底部安全区域（`safe-area-inset-*`）适配。
- 横竖屏切换，组件状态保持。
- 触屏设备上的点击热区是否足够大（至少 44x44pt）。

------

## 四、自测工具与技巧

- **浏览器 DevTools**：切换设备、网速模拟（Slow 3G）、断点调试、元素审查。
- **抓包工具**：Charles/Whistle，修改接口返回数据模拟边界、异常。
- **Mock 数据**：在代码中临时注入假数据，快速验证 UI 和空值态。
- **Vue/React DevTools**：检查组件状态、Props、Events 是否正确。
- **aXe/Lighthouse**：检查无障碍、性能、最佳实践。
- **代码扫描**：ESLint + Prettier 保证风格一致，TypeScript 减少低级错误。
