## 0. 怎么用这份清单

### 三种用法

1. **发给 AI**：勾选若干题 + 附上仓库路径，要求 AI 把答案写到 `docs/项目认识-答案.md`（见附 A 话术、附 C 模板）。
2. **问同事**：按风险排序，一次 3–5 题，带上下文去问（见附 B 一页纸）。
3. **自查**：先自己从 README、`package.json`、目录结构推一遍，标出空白项再去验证。

### 答案来源标记

每题后标注来源，方便判断该问谁：

- `[代码]` 可从代码验证
- `[文档]` README / wiki / ADR / CHANGELOG
- `[同事]` 必须问人（约定、流程、历史）
- `[线上]` 需要看运行环境 / 监控 / 配置

### 事实 vs 约定

- **事实**：可从代码/文档验证（技术栈、入口、路由、请求封装）。
- **约定**：只能问人（分支策略、提测流程、谁负责、危险区）。
> 拿不准时，先按事实查，查不到再按约定问。

### 阻塞优先级

- `[阻塞]` 不解决就开不了工（依赖、登录、环境、权限）。
- `[重要]` 影响正确性与协作（请求、鉴权、规范、流程）。
- `[可后置]` 业务细节、历史、性能，可边做边查。

### 风险排序原则

阻塞 → 重要 → 可后置；先能跑起来，再摸骨架，再画业务地图，最后跟一次完整交付。

## 十一、问人好习惯

1. **先给结论再问**：我猜是 X，对吗？
2. **一次问 3–5 个**，不要甩 30 个清单。
3. **要链接不要口述**：仓库、YApi、设计稿、流程文档。
4. **记回文档**：把答案写回本清单，下次自己和后来人受益。
5. **区分「事实」和「约定」**：事实可从代码验证；约定必须问人。
6. **问人时带上下文**：说清你已看过什么、猜到什么，只问缺口。

## 附 A：发给 AI 的话术

```text
这是我接手的新项目。请按 docs/接手新项目-终极提问清单.md 逐题调研代码库，
把答案写到 docs/项目认识-答案.md（不要改业务代码）。
优先读：README、package.json、入口、路由/页面配置、请求层、状态管理、环境配置。
结论要可落地：给出关键文件路径，方便我点进去。
不确定的地方明确写「未从代码确认」，不要编造。
只答我勾选的题。
```

可选补充（越具体越好）：

- 「我主要负责 XXX 模块 / 页面」
- 「先讲怎么跑起来，再讲业务」
- 「对照某套规范 / 旧项目差异」

## 附 D：阅读优先级（给 AI / 也给自己）

1. `README.md`、`package.json`（或 `go.mod` / `pom.xml` / `requirements.txt`）
2. 入口：`src/main.js`、`src/App.vue`（或 `app.ts` / `main.go` / `Application.java`）
3. 路由：`src/pages.json`（或 `router/`、`controller/`）
4. 环境与请求：`env`、`request` / `config`
5. 状态：`store`（或 `service` / `repository`）
6. 再按你负责的业务模块 / 分包深入
