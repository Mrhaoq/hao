#  HTML/CSS 面试题（面试级解答）

## 1. HTML5 新特性
**回答**：  
> 在千源百荟回收项目中，我们深度应用了：  
> - **语义化标签**：官网用 `<section>` 替代 `<div>`，提升 SEO（如新闻资讯模块）  
> - **Geolocation**：小程序通过 `navigator.geolocation` 实现门店精准定位  
> - **本地存储**：SaaS 后台用 `localStorage` 缓存全国地区数据，减少 80% 接口请求  
> *（简历关联：项目三中“减少重复接口请求”）*

## 2. HTML 语义化理解
**回答**：  

> 语义化让 HTML 结构表达内容含义，**三大好处**：  
> 1. **SEO 优化**：搜索引擎识别 `<nav>`/`<article>`（官网导航栏用 `<nav>`）  
> 2. **可访问性**：屏幕阅读器能解析语义标签（如 `<button>` 代替 `<div>`）  
> 3. **维护性**：团队协作时逻辑清晰（回收小程序用 `<main>` 区分核心内容）  
> *（项目验证：铅蛋小程序“电池回收流程”用 `<ol>` 列表实现）*

## 3. DOCTYPE 作用
**回答**：  
> `<!DOCTYPE html>` 告诉浏览器用 W3C 标准解析 HTML。  
> **关键区别**：  
> - **标准模式**：完全遵循规范（必须写）  
> - **混杂模式**：模拟 IE5/6 行为（因省略 DOCTYPE 导致布局错乱）  
> *（避坑案例：SaaS 后台因忘记写 DOCTYPE，导致 Flex 布局失效）*

## 4. viewport meta 标签
**回答**：  
> 解决移动端布局问题，**核心配置**：  
> ```html
> <meta name="viewport" content="width=device-width, initial-scale=1.0, user-scalable=no">
> ```
> **作用**：  
> - `width=device-width`：页面宽度 = 设备宽度  
> - `user-scalable=no`：禁止缩放（小程序避免误触缩放）  
> *（项目应用：铅蛋小程序解决 iOS 13+ 状态栏溢出问题）*

## 5. CSS 盒模型
**回答**：  
> **标准盒模型**：`width = 内容宽度`（W3C 标准）  
> **怪异盒模型**：`width = 内容 + padding + border`（IE 怪异模式）  
> **解决方案**：  
> ```css
> * { box-sizing: border-box; } /* 项目工程化规范 */
> ```
> *（简历关联：ElementPlus 组件库封装中强制使用）*

## 6. BFC 机制
**回答**：  
> BFC（Block Formatting Context）是独立渲染区域，**解决两个问题**：  
> 1. **外边距重叠**：给 `.table-row` 添加 `overflow: hidden`（SaaS 后台表格）  
> 2. **浮动元素包裹**：Swiper 轮播图用 `overflow: hidden` 避免父容器塌陷  
> *（项目验证：铅蛋小程序轮播图优化）*

## 7. Flex vs Grid
**回答**：  
> **Flex 一维布局**：适合行内元素（如导航栏 `justify-content: space-around`）  
> **Grid 二维布局**：适合复杂网格（如 SaaS 后台数据看板 `grid-template-columns: repeat(3, 1fr)`）  
> *（项目选择：官网商品展示用 Grid，小程序底部导航用 Flex）*

## 8. CSS 选择器优先级
**回答**：  
> 优先级顺序：`!important > ID > Class > Tag`  
> **避坑**：  
> - 避免 `*` 通配符（影响性能）  
> - 用 `:deep` 深度选择器覆盖第三方样式（如 ElementPlus）  
> *（组件库实践：`qd-*` 组件中使用 `:deep(.el-button)`）*

## 9. CSS3 新特性应用
**回答**：  
> - **transition**：订单状态切换（`transition: all 0.3s`）  
> - **transform**：Swiper 轮播图用 `transform: translateX()` 实现无缝滚动  
> - **animation**：电池回收进度条用 `@keyframes` 动画  
> *（项目验证：千源百荟小程序“订单状态”过渡）*

## 10. 1px 边框实现
**回答**：  
> **移动端 1px 边框解决方案**：  
> ```css
> .border-1px {
> position: relative;
> }
> .border-1px::after {
> content: '';
> position: absolute;
> left: 0;
> bottom: 0;
> width: 100%;
> height: 1px;
> transform: scaleY(0.5);
> background: #000;
> }
> ```
> *（项目应用：铅蛋小程序订单列表清晰分隔线）*

## 11. 画三角形
**回答**：  
> **原理**：利用 `border` 相邻边相交形成三角  
> ```css
> .triangle {
> width: 0;
> height: 0;
> border-left: 50px solid transparent;
> border-right: 50px solid transparent;
> border-bottom: 100px solid #f00;
> }
> ```
> *（项目案例：回收小程序“电池等级”标签用三角形图标）*

## 12. 响应式 vs 自适应
**回答**：  
> **响应式**：媒体查询 `@media` 动态调整布局（官网适配手机）  
> **自适应**：固定多套布局 + `rem` 适配（小程序用 `rem` + `postcss-pxtorem`）  
> *（项目选择：官网用响应式，小程序用自适应）*

#  JavaScript 面试题（面试级解答）

## 1. 原始 vs 引用数据类型
**回答**：  
> **原始类型**：`string/number/boolean/null/undefined/symbol`（值存储在栈）  
> **引用类型**：`object/array/function`（值存储在堆，复制的是引用地址）  
> *（项目案例：SaaS 后台用 `JSON.parse(JSON.stringify(obj))` 深拷贝订单数据）*

## 2. == vs === 区别
**回答**：  
> **==**：松散相等，会进行类型转换（`5 == '5'` → `true`）  
> **===**：严格相等，不进行类型转换（`5 === '5'` → `false`）  
> **关键陷阱**：  
> - `0 == false` → `true`  
> - `null == undefined` → `true`，但 `null === undefined` → `false`  
> *（项目避坑：回收小程序权限校验强制用 `===`）*

## 3. 闭包的应用与内存问题
**回答**：  
> **应用场景**：  
> - 模块化封装（`api.js` 中请求方法）  
> - 防抖节流（`utils.js` 中 `debounce` 函数）  
> **内存问题**：避免在循环中创建闭包（用 `let` 代替 `var`）  
> *（项目案例：铅蛋小程序用闭包封装 `getToken` 避免重复请求）*

## 4. 作用域与作用域链
**回答**：  
> **作用域链**：访问变量时，从当前作用域向上查找（自身 → 父作用域 → 全局）  
> **关键点**：  
> - `var` 有函数作用域  
> - `let/const` 有块级作用域  
> *（面试示例）：  
> ```javascript
> function outer() {
>   let a = 1;
>   function inner() { console.log(a); } // 通过作用域链访问
>   return inner;
> }
> ```*

## 5. this 指向问题
**回答**：  
> **this 指向由调用方式决定**：  
> - 函数调用：`this` → `window`（严格模式 `undefined`）  
> - 对象方法：`this` → 调用对象  
> - 构造函数：`this` → 新实例  
> - `call/apply/bind`：显式绑定  
> *（项目避坑：Vue 组件中用箭头函数避免 `this` 指向错误）*

## 6. 原型与原型链
**回答**：  
> **原型**：`function.prototype` 指向原型对象  
> **原型链**：对象属性查找路径（自身 → 原型 → `Object.prototype`）  
> *（项目应用：`utils.js` 中用原型扩展 `String.prototype.formatNumber`）*

## 7. 继承方式
**回答**：  
> **组合继承**（最常用）：  
> ```javascript
> function Parent() { this.name = 'parent'; }
> Parent.prototype.say = function() { console.log(this.name); };
> function Child() { Parent.call(this); } // 构造函数继承
> Child.prototype = Object.create(Parent.prototype); // 原型链继承
> ```
> *（项目关联：`qd-*` 组件库用组合继承实现 `BaseComponent` 基类）*

## 8. ES6 新特性
**回答**：  
> **核心优势**：  
> - `let/const`：块级作用域（避免 `var` 变量提升）  
> - 箭头函数：无 `this` 绑定（适合回调）  
> - 解构赋值：简化对象/数组取值  
> *（项目案例：Vue3 组件中 `const { state, dispatch } = useStore()`）*

## 9. Promise vs async/await
**回答**：  
> **原理**：  
> - `Promise`：异步操作容器（`pending` → `fulfilled`/`rejected`）  
> - `async/await`：Promise 语法糖，使异步代码同步化  
> *（项目优势）：  
> ```javascript
> async function pay() {
>   const token = await getToken(); // 无阻塞等待
>   await requestPay(token);
> }
> ```
> *（简历关联：回收小程序优化支付流程）*

## 10. 事件循环
**回答**：  
> **执行顺序**：  
> 1. 同步代码  
> 2. 微任务（`Promise`）  
> 3. 宏任务（`setTimeout`）  
> *（面试示例）：  
> ```javascript
> console.log('start');
> setTimeout(() => console.log('timeout'), 0);
> Promise.resolve().then(() => console.log('promise'));
> console.log('end');
> // 输出：start → end → promise → timeout
> ```*

## 11. 深拷贝 vs 浅拷贝
**回答**：  
> **浅拷贝**：`Object.assign`/`...`（只复制第一层）  
> **深拷贝**：`JSON.parse(JSON.stringify(obj))` 或 `lodash.cloneDeep`  
> *（项目避坑）：  
> - `JSON.parse` 无法拷贝函数/`undefined`/`Date`  
> - SaaS 权限模块用深拷贝避免修改原始数据（简历“权限管控模块”）*

## 12. 防抖 vs 节流
**回答**：  
> **防抖**：多次触发后只执行最后一次（搜索框输入）  
> **节流**：固定时间间隔执行（滚动事件）  
> *（实现代码）：  
> ```javascript
> // 防抖
> function debounce(fn, delay) {
> let timer;
> return (...args) => {
>  clearTimeout(timer);
>  timer = setTimeout(() => fn.apply(this, args), delay);
> };
> }
> ```
> *（项目应用：铅蛋小程序搜索框用防抖，长列表用节流）*

## 13. 数组 API 应用
**回答**：  
> **map**：生成新数组（订单数据转换）  
> **filter**：筛选数据（过滤待处理订单）  
> **reduce**：聚合数据（计算订单总金额）  
> *（项目案例）：  
> ```javascript
> // 计算总金额
> const total = orders.reduce((sum, order) => sum + order.amount, 0);
> ```
> *（简历关联：SaaS 后台财务结算模块）*

## 14. 正则表达式
**回答**：  
> **核心用法**：`/pattern/flags`  
> *（项目应用）：  
> - 手机号验证：`/^\d{11}$/`  
> - 金额格式化：`amount.toFixed(2).replace(/\B(?=(\d{3})+(?!\d))/g, ',')`  
> *（简历关联：回收小程序电池型号校验 `^EB\d{4}$`）*



# Vue 相关面试题（面试级解答）

## 1. Vue2 与 Vue3 核心区别

**回答**：  

> **核心区别**：响应式系统（Vue3 用 Proxy 代替 Vue2 的 `Object.defineProperty`）和性能优化。  
> *（项目验证）：  
> - 千源百荟回收系统（Vue3）：直接修改 `order.status` 无需 `this.$set`（Vue2 需 `this.$set`）  
> - 铅蛋小程序：Vue3 编译优化使首屏加载时间降低 40%（简历成果）*

## 2. Composition API vs Options API
**回答**：  
> **Composition API**（`<script setup>`）：逻辑按功能组织（如 `useOrder`），**复用性更高**；  
> **Options API**：按选项组织（`data`/`methods`），**适合小型项目**。  
> *（简历实践）：  
> 千源百荟项目强制使用 Composition API，使代码复用率提升 30%（简历“封装 15+ 业务组件”）*

## 3. Vue 响应式原理
**回答**：  
> **Vue2**：`Object.defineProperty` 劫持属性，`getter` 收集依赖，`setter` 派发更新；  
> **Vue3**：`Proxy` 代理对象，`get`/`set` 操作自动收集/派发。  
> *（项目痛点）：  
> SaaS 后台（Vue2）需用 `this.$set` 添加字段 → 千源百荟（Vue3）直接赋值即可*

## 4. 虚拟 DOM 与 diff 算法
**回答**：  
> **虚拟 DOM**：JS 对象描述真实 DOM，减少直接操作；  
> **diff 算法**：双端比较 + `key` 优化（`v-for` 必须加 `key`）。  
> *（项目优化）：  
> 铅蛋小程序长列表：`v-for` 用 `:key="item.id"`，使滚动流畅度提升 30%（简历“长列表卡顿优化”）*

## 5. Vue 组件生命周期
**回答**：  
> **关键钩子**：  
> - `mounted`：初始化地图定位（千源百荟官网）  
> - `beforeUnmount`：清理 WebSocket（铅蛋小程序）  
> - `onActivated`：缓存页面状态（SaaS 后台 `Keep-alive`）  
> *（简历关联）：SaaS 后台“角色权限管理”使用 `activated` 恢复状态*

## 6. 组件通信
**回答**：  
> **父子**：`props` + `$emit`（订单列表传递数据）  
> **跨级**：`provide/inject`（SaaS 后台权限模块）  
> *（项目实践）：  
> ```vue
> <!-- 父组件 -->
> <script setup>
> provide('userRole', 'admin')
> </script>
> 
> <!-- 子组件 -->
> <script setup>
> const userRole = inject('userRole') // 直接获取
> </script>
> ```

## 7. Vue Router 原理
**回答**：  
> **核心**：基于 `history`/`hash` API 监听 URL 变化，匹配路由配置。  
> *（简历落地）：  
> 铅蛋小程序：用 `beforeEach` 实现**动态权限路由**（简历“多角色动态路由加载”）  
> 懒加载：SaaS 后台对 `CustomerManage` 组件启用懒加载，包体积减少 25%*

## 8. Vuex vs Pinia
**回答**：  
> **Vuex**（Vue2）：`state`/`mutations`/`actions`，**同步操作**（复杂逻辑难维护）；  
> **Pinia**（Vue3）：**模块化**、**TypeScript 友好**、**无 mutations**。  
> *（项目对比）：  
> SaaS 后台（Vue2）用 Vuex → 千源百荟（Vue3）用 Pinia，状态管理代码量减少 40%*

## 9. Vue 指令原理
**回答**：  
> **`v-if`**：编译时条件渲染，**销毁/重建 DOM**（用在支付弹窗）；  
> **`v-model`**：语法糖 = `:value` + `@input`。  
> *（项目避坑）：  
> 千源百荟官网：`v-if` 控制弹窗（避免重复渲染），**不用 `v-show`**（简历“性能优化”）*

## 10. 插槽与作用域插槽
**回答**：  
> **普通插槽**：内容分发（`qd-Button` 自定义文本）；  
> **作用域插槽**：子组件向父组件传递数据（`OrderList` 暴露 `order`）。  
> *（简历关联）：  
> 封装 `qd-*` 组件库时，用作用域插槽实现 15+ 通用组件复用（简历“封装 15+ 业务组件”）*

## 11. Keep-alive 原理
**回答**：  
> **原理**：缓存路由组件实例，**避免重复挂载**（通过 `activated`/`deactivated` 钩子）。  
> *（项目应用）：  
> SaaS 后台 `OrderDetail` 页面：  
> ```vue
> <keep-alive include="OrderDetail">
> <router-view></router-view>
> </keep-alive>
> ```
> *（关键点）：需在 `activated` 恢复数据（如重新获取订单详情）*

## 12. ref vs reactive
**回答**：  
> **`ref`**：包装**原始值**（需 `.value` 访问）→ 用在简单值（按钮状态）；  
> **`reactive`**：包装**对象**（直接访问属性）→ 用在数据对象（用户信息）。  
> *（项目实践）：  
> ```javascript
> // ref 用于简单值
> const isSubmitting = ref(false)
> 
> // reactive 用于对象
> const user = reactive({ name: '张三' })
> ```

## 13. setup 语法糖
**回答**：  
> **`<script setup>`**：Vue3 语法糖，**自动暴露**顶层变量到模板。  
> *（简历优势）：  
> 千源百荟项目中，用 `setup` 语法糖使组件代码量减少 40%（如 `useStore` 直接解构）  
> ```vue
> <script setup>
> import { ref } from 'vue'
> const count = ref(0)
> const increment = () => count.value++
> </script>
> ```

# TypeScript 面试题（面试级解答）

## 1. TypeScript 与 JavaScript 区别
**回答**：  
> **TypeScript** = JavaScript + **类型系统**（静态类型检查）+ **高级特性**（泛型、装饰器）。  
> *（项目价值）：  
> 千源百荟项目（Vue3 + TypeScript）：  
> - 类型推断减少 50% 类型错误  
> - 代码可维护性提升（团队协作时接口定义清晰）*

## 2. TypeScript 基本类型
**回答**：  
> **核心类型**：`string`、`number`、`boolean`、`null`、`undefined`、`object`、`array`、`tuple`、`enum`、`any`。  
> *（项目实践）：  
> SaaS 后台权限模块：  
> ```typescript
> interface Role {
> id: number;
> name: string;
> permissions: string[]; // 数组类型
> }
> ```

## 3. interface vs type
**回答**：  
> **`interface`**：扩展性好（可重复声明），**适合对象结构**；  
> **`type`**：类型别名，**适合复杂类型**（联合类型、元组）。  
> *（简历案例）：  
> 千源百荟项目中，`interface` 定义 API 响应结构，`type` 定义 `OrderStatus = 'pending' | 'completed'`*

## 4. TypeScript 泛型
**回答**：  
> **作用**：**类型参数化**，使函数/组件可处理多种类型。  
> *（项目应用）：  
> ```typescript
> // 通用 API 请求
> const request = async <T>(url: string): Promise<T> => {
> const res = await fetch(url);
> return res.json() as T;
> };
> 
> // 使用：获取订单列表
> const orders = await request<Order[]>(`/api/orders`);
> ```

## 5. TypeScript 装饰器
**回答**：  
> **作用**：**修改类/方法**（如 `@Component` 在 Vue 中）。  
> *（项目实践）：  
> 千源百荟组件库封装：  
> ```typescript
> @Component
> export default class OrderItem extends Vue {
> // ...
> }
> ```

## 6. TypeScript 模块系统
**回答**：  
> **ES 模块**（`import/export`）：**默认方案**（Vue3 项目）；  
> **CommonJS**（`require`）：**旧项目**（如 Vue2）。  
> *（简历关联）：  
> 项目中统一使用 ES 模块（`import { ref } from 'vue'`），避免 `require` 问题*

## 7. 类型推断
**回答**：  
> **原理**：TS 通过**上下文**自动推导类型（无需显式声明）。

# Vue 指令原理（面试级解答）

## 1. v-if 与 v-show 核心区别
**回答**：  
> **`v-if`**：**编译时**条件渲染，**销毁/重建 DOM**（适合条件不常切换的场景）；  
> **`v-show`**：**运行时**切换 `display: none`，**保留 DOM**（适合频繁切换的场景）。  
> *（项目实践）：  
> 千源百荟支付流程中，用 `v-if` 控制支付弹窗（避免重复渲染）：  
> ```vue
> <div v-if="showPayModal">
> <PaymentComponent />
> </div>
> ```
> *（避坑点）：  
> 铅蛋小程序长列表中，**避免**用 `v-show` 代替 `v-if`（因列表项数量多，`display: none` 仍会渲染，导致性能下降）。*

## 2. v-for 与 key 优化原理
**回答**：  
> **`v-for`**：循环渲染组件，**`key` 用于 diff 算法**（唯一标识）；  
> **关键点**：  
> - **避免用 index 作为 key**（导致虚拟 DOM 重建）；  
> - **必须用唯一标识**（如 `item.id`）。  
> *（项目优化案例）：  
> 铅蛋小程序订单列表（长列表）：  
> ```vue
> <!-- 错误：用 index 作为 key -->
> <div v-for="(item, index) in orders" :key="index">...</div>
> 
> <!-- 正确：用唯一 ID -->
> <div v-for="item in orders" :key="item.id">...</div>
> ```
> *（成果关联）：简历中“长列表卡顿优化”，通过正确使用 `key` 使滚动流畅度提升 30%。*

## 3. v-model 的底层原理
**回答**：  
> **`v-model` 是语法糖**，等价于 `:value` + `@input`：  
> ```vue
> <!-- 原始写法 -->
> <input :value="message" @input="message =  $ event.target.value" />
> 
> <!-- v-model 简写 -->
> <input v-model="message" />
> ```
> *（项目深度应用）：  
> 在 SaaS 后台表单中，自定义组件使用 `v-model`：  
> ```vue
> <!-- 自定义输入组件 -->
> <template>
> <input
>  :value="modelValue"
>  @input=" $ emit('update:modelValue',  $ event.target.value)"
> />
> </template>
> 
> <!-- 使用 -->
> <CustomInput v-model="user.name" />
> ```
> *（扩展场景）：  
> **多值绑定**：`v-model:prop`（如 `v-model:isEditing`），用于组件接收多个属性。*

## 4. 自定义指令原理
**回答**：  
> **指令生命周期**：`bind`（挂载）→ `inserted`（DOM 插入）→ `update`（更新）→ `componentUpdated`（组件更新）→ `unbind`（销毁）。  
> *（项目实战案例）：  
> 在千源百荟中，封装 `v-debounce` 防抖指令：  
> ```javascript
> // 注册指令
> app.directive('debounce', {
> mounted(el, binding) {
>  let timer;
>  el.addEventListener('input', () => {
>    clearTimeout(timer);
>    timer = setTimeout(() => {
>      binding.value();
>    }, 300);
>  });
> }
> });
> 
> // 使用
> <input v-debounce="handleSearch" />
> ```
> *（简历关联）：简历中“落地全链路性能优化方案，实现请求防抖节流”。*

# Vue Keep-alive 组件（面试级解答）

## 1. Keep-alive 核心原理
**回答**：  
> **原理**：通过缓存组件实例**避免重复挂载**，利用 `activated`/`deactivated` 生命周期钩子管理缓存状态。  
> *（底层机制）：  
> - 组件首次渲染后，存储在 `cache` 对象中  
> - 路由切换时，**不销毁组件**，而是将其移入缓存  
> - 重新激活时，触发 `activated` 钩子恢复状态  
> ```javascript
> // Vue 源码简化逻辑
> export default {
>   mounted() {
>     this. $ vnode = this. $ vnode; // 保留虚拟节点
>     this. $ options._cache = this. $ options._cache || {};
>   },
>   deactivated() {
>     this. $ options._cache[this._uid] = this; // 缓存实例
>   },
>   activated() {
>     this. $ options._cache[this._uid] = null; // 从缓存移除
>     // 恢复状态逻辑
>   }
> }
> ```

## 2. Keep-alive 实战应用（SaaS 后台案例）
**回答**：  
> **典型场景**：需要**保留状态**的页面（如表单、列表），避免重复请求。  
> *（项目实践）：  
> 在 SaaS 管理后台的订单详情页：  
> ```vue
> <!-- 路由配置 -->

> </keep-alive>
> 
> <!-- 组件中使用 -->
> <script setup>
> import { onActivated } from 'vue'
> 
> onActivated(() => {
> // 恢复表单状态（重新获取数据）
> fetchOrderDetail()
> })
> 
> const fetchOrderDetail = async () => {
> const order = await api.getOrder(orderId)
> form.value = order
> }
> </script>
> ```
> *（关键价值）：  
> 简历中“订单详情页状态保留优化”，通过 Keep-alive 使用户返回时**无需重新加载数据**，提升体验 35%（避免重复请求 100+ 次/天）。*

## 3. include/exclude 与缓存控制
**回答**：  
> **核心配置**：  
> - `include`：**缓存指定组件**（`<keep-alive include="OrderDetail,UserList">`）  
> - `exclude`：**排除指定组件**（`<keep-alive exclude="Login">`）

## 4. max 属性与缓存管理
**回答**：
