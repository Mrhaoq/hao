# AI 加速开发八件套

换一家公司时，用这份清单加快读代码、改代码、修 bug、跑仓库里已有的检查、自己看 diff。

个人站的日常练法看 `cursor/用AI加快写代码.md`。要开发一个 Agent 产品，看 `cursor/前端转Agent学习清单.md`。

---

## 新公司第一周先对上的四件事

入职后先找这四样。找到了就能开始用 AI 改代码。不要把后面的四周课程当成第一周必须逐项做完。

1. **规矩在哪**：已有的 `AGENTS.md`、`.cursor/rules`、`CLAUDE.md`，或写在 README 里的规范。有就遵守，没有再补短的几条。
2. **这次要带上的材料**：相关文件、报错、接口说明。这些材料属于这一轮 Prompt。
3. **怎样算改对**：仓库里现成的测试、lint、类型检查、启动命令，再加上自己看 diff。
4. **一次只改一小块**：先计划，再改，再跑上面的检查。

---

## 0. 学习目标

不是成为 Agent 研究员，而是做到：

能用 AI 更快地读代码、写代码、修 bug、跑测试、做 review、提交。

学习原则：

- 项目驱动：每学一个，立刻用在真实代码库。
- 先会用，再懂原理。
- 小步快跑：一次只让 AI 改一点。
- 永远 review：AI 是实习生，不是老板。
- 建立闭环：Prompt → 改代码 → 跑测试 → 检查 diff。

## 1. 八件套地图

| 模块 | 一句话 | 优先级 |
| --- | --- | --- |
| LLM | 选哪个 AI 大脑 | 必会 |
| Prompt | 怎么下指令 | 必会 |
| Context | 给它看什么资料 | 必会 |
| Rules | 项目规矩 | 必会 |
| Agent Mode | 让它自动多步干活 | 必会 |
| Tools / MCP | 让它能动手 | 常用 |
| Skills / Commands | 把重复流程打包 | 加分 |
| Test / Eval | 检查它干得对不对 | 必会 |

## 2. 分阶段学习路线

### 第 1 周：LLM + Prompt

目标：会稳定地让 AI 帮你写代码、解释代码、写测试。

学：

- 常见模型区别：代码强、推理强、长上下文、便宜快
- Prompt 基本结构：角色、目标、上下文、约束、步骤、输出格式
- 常用 Prompt 模板：解释代码、修 bug、写单测、重构、code review

练：

- 同一个任务，换 3 个模型对比
- 写 5 个你每天都会用的 Prompt 模板

验收：

- 能写出让 AI 稳定输出 JSON / diff / 测试用例的 Prompt

### 别问「有没有什么可优化的」

这句话不是错，而是太泛。模型会给一堆跟这轮无关的建议。更好的问法核心是：**加标准、限范围、给优先级、要验证、没有就说没有。**

必须改 = P0：正确性、会导致 bug 的边界、测试失败、安全、明显性能退化。可读性默认 P2。日常收工用最简版或代码场景版，不要每次把六个维度全打开。

点名文件或 diff。最多列几条。先方案，你点头再改。这个站的验证以打开页面和看 diff 为主；仓库里没有测试或基准，就不要写「先跑基准」。

| 八件套 | 关联度 | 怎么关联 |
| --- | --- | --- |
| Prompt | 核心 | 「有没有可优化项」本身就是 Prompt 写法问题 |
| Context | 核心 | 要给它代码、diff、目标、约束、报错、测试结果 |
| Rules | 核心 | 让它按 `AGENTS.md` / `.cursor/rules` 审查 |
| Test / Eval | 核心 | 每个优化项都要有验证方式，不能凭感觉 |
| Tools / MCP | 常用 | 让它实际跑测试、lint、类型检查；没有这些命令就跑你写的验收 |
| Agent Mode | 常用 | 计划 → 审查 → 验证 → 总结，但别自动乱改 |
| Skills / Commands | 加分 | 同一句每周都在问，再收成 `/review`；现在不要新建 `/optimize` |
| LLM | 次要 | 复杂 review 用强推理模型，简单格式化用快模型 |

原来那句话主要只用了 Prompt 一点点。升级后同时用到 Prompt + Context + Rules + Test/Eval，再配合 Tools / Agent Mode 更好。

**一句话（日常收工就贴这句）：**

```text
基于当前目标和项目规则，只针对这次输出，按正确性、边界、性能、安全、测试列 P0/P1/P2 优化项，每条给证据和验证方式。没有必须改的就直说，先别改代码。
```

**最简日常版：**

```text
请按正确性、边界、性能、安全、测试五个维度，给这次输出列 P0/P1/P2 优化项。
每条给证据和验证方式。
没有必须改的就直说。
先别改代码。
范围：只针对刚才的代码或回答，不要扩展到无关部分。
```

**代码场景版（改完代码默认用这个）：**

```text
请基于 AGENTS.md、.cursor/rules 和这次 diff 做 review。
只提会导致 bug、测试失败、性能退化、安全风险的问题。
按严重程度排序。
没有就明确说没有。
先别改代码。
范围：只看刚才的 diff 和我点名的文件，不要扫全库。
```

**万能升级版（目标不清、要一次做完整 review 时再用；不要当每天的默认）：**

```text
请对刚才的输出做一次 review。

目标：<这一轮要哪一种检查>
约束：遵守 AGENTS.md / .cursor/rules；可读性只标 P2；先别改代码
范围：只针对刚才的代码或回答，不要扩展到无关部分。

检查维度：正确性、边界条件、性能、安全、可读性、测试覆盖。

输出格式：
1. 有没有必须改的？没有就直说。
2. 问题列表（最多 5 条）：
   优先级 P0/P1/P2 | 位置 | 证据 | 影响 | 建议 | 验证方式
3. 如果只能改一处，改哪里？为什么？
4. 先别改代码，只给方案。
```

**答案场景版（review 的是说明，不是 diff）：**

```text
请从准确性、完整性、可执行性、是否遗漏反例四个角度 review 刚才的回答。
指出必须补充和可选补充的内容。
如果已经足够，就直说不用改。
```

**性能优化版（仓库里真有测试或基准再用）：**

```text
请先跑测试/lint/基准，再根据结果给优化项。
不要凭感觉。
给出优化前后对比、成本和风险。
没有这些命令就写「无基准，无法判断」，不要编数字。
```

**安全审查版：**

```text
请从 Prompt Injection、权限、密钥泄露、依赖风险、输入边界五个角度 review。
按 P0/P1/P2 列出问题，并给验证方式。
没有必须改的就直说。先别改代码。
```

本仓库套进代码场景版的例子：

```text
请基于 AGENTS.md、.cursor/rules/personal-site.mdc 和这次 diff 做 review。
只提会导致 bug、测试失败、性能退化、安全风险、或违反单域名/catalog/存储键的问题。
范围：只看刚才的 diff，以及
apps/web/src/shared/catalog/index.ts
apps/web/src/home/App.tsx
不要扫其他功能目录。
按 P0/P1/P2 排序。每条写：位置 | 证据 | 影响 | 建议 | 验证方式。
验证：首页搜索「抽奖」能出卡片；直接打开 /lottery/ 不用从首页进；键名仍是 hao.lottery.v1。
没有必须改的就直说。先别改代码。
如果只能改一处，改哪里？为什么？
```

你点头之后再动手：

```text
按 P0 第 1 条改。只改列出的文件，改完跑我说过的验收，最后用几句话总结 diff。不要做列表里没点名的事。
```

### 第 2 周：Context + Rules

目标：让 AI 知道“看哪些文件”和“遵守什么规矩”。

学：

- Context：@文件、目录、报错日志、相关代码、需求文档
- 最小必要上下文：不要一次塞整个仓库
- Rules 文件：`AGENTS.md`、`CLAUDE.md`、`.cursor/rules`
- 项目规则应包含：技术栈、常用命令、代码风格、测试要求、禁止事项、提交规范

练：

- 给你的项目写一个 `AGENTS.md`
- 让 AI 只根据指定文件修一个小 bug

验收：

- AI 不再乱改无关文件
- 你能说清“这次任务需要哪些上下文”

### 第 3 周：Agent Mode + Tools / MCP

目标：让 AI 自己读代码、改代码、跑测试、总结。

学：

- Agent Mode：计划 → 执行 → 验证 → 总结
- 最大步数、终止条件、防死循环
- Tools：终端、文件、浏览器、GitHub、数据库
- MCP：让 AI 连接外部工具和服务的协议

练：

- 对 AI 说：先给计划，再小步修改，改完跑测试，最后总结 diff。
- 配置一个 MCP，让 AI 能查 issue、跑命令或读数据库

验收：

- AI 能自主完成一个小 bug 修复，并跑通测试

### 第 4 周：Skills / Commands + Test / Eval

目标：把重复流程封装，并建立质检习惯。

学：

- Skills / Commands：把常用流程变成 `/fix-bug`、`/review`、`/commit`
- Test / Eval：单元测试、lint、类型检查、构建、diff review、AI 自检
- 完成定义 DoD：代码能跑、测试通过、diff 合理、无敏感信息

练：

- 写 3 个自定义命令：修 bug、review、提交
- 给项目加一个 AI 辅助测试流程

验收：

- 你能把一套重复开发流程交给 AI 半自动完成

## 3. 每件套详细学习卡

### ① LLM

- 学：模型选择、成本、速度、上下文长度
- 练：同一任务换模型对比
- 验收：知道什么任务用什么模型

### ② Prompt

- 学：角色、目标、上下文、约束、步骤、输出格式
- 练：写 5 个常用模板
- 验收：输出稳定、可复用

### ③ Context

- 学：给最小必要信息
- 练：@文件、报错、日志、相关代码
- 验收：AI 不乱猜、不乱改

### ④ Rules

- 学：项目规矩文件
- 练：写 `AGENTS.md`
- 验收：AI 遵守技术栈、命令、风格

### ⑤ Agent Mode

- 学：计划-执行-验证循环
- 练：让 AI 自主修一个小 bug
- 验收：能跑测试、能总结 diff

### ⑥ Tools / MCP

- 学：终端、浏览器、GitHub、数据库
- 练：配置一个 MCP
- 验收：AI 能动手查资料、跑命令

### ⑦ Skills / Commands

- 学：把重复流程打包
- 练：写 `/fix-bug`、`/review`、`/commit`
- 验收：重复任务一键触发

### ⑧ Test / Eval

- 学：测试、lint、类型、构建、review
- 练：建立完成定义
- 验收：不盲目信任 AI 输出

## 4. 综合实战项目

选一个你熟悉的小项目，完成一次完整流程：

1. 写 `AGENTS.md`
2. 让 AI 读需求和相关文件
3. 让 AI 先给计划
4. 小步修改代码
5. 跑测试 / lint / 构建
6. 让 AI 总结 diff
7. 你做 review
8. 提交

用到的就是八件套。

## 5. 避坑清单

- 上下文太少：AI 乱猜
- 上下文太多：AI 迷路
- 没有 Rules：AI 乱改风格
- 不跑测试：改完就崩
- 不 review：埋雷
- 一次改太多：无法定位问题
- 问「有没有可优化的」：等于一次改太多
- 六个维度全开当日常收工：可读性会堆出一串 P2
- 盲目信任：AI 会自信地犯错

## 6. 一句话总结

LLM 选大脑，Prompt 下指令，Context 给资料，Rules 定规矩，Agent Mode 自动干，Tools/MCP 给手脚，Skills/Commands 包流程，Test/Eval 做质检。

---

## 先不要按周新建的东西

第一周对上前面四件事之后，日常开发用团队已经在用的模型和检查命令即可。下面这些等同一类纠正重复出现，或公司已经在用，再补：

- 换三个模型对比：先用团队统一的那个。某个任务明显又慢又容易错，再换。
- 自己写 `/fix-bug`、`/review`、`/commit`：公司若已有 Skill 或命令，先用他们的。
- 配置 MCP、连数据库：编辑器里读文件和跑终端已经能改代码、跑测试。查 Issue、查内部系统变成每天的重复动作时，再接 MCP。
- 单独做一套 AI 评估平台：质检就是这家仓库已有的测试和你的 review。
